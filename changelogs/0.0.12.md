# Autohand 0.0.12

This release makes Autohand Desktop easier to set up, navigate, and extend.

## Changed

- A dedicated icon navigation rail replaces the Autohand Code/Studio dropdown. Choose the compact rail or sidebar labels in Appearance; your choice is saved.
- First-run onboarding now guides you through connecting an agent, choosing a default harness, adding a project, and starting your first thread. You can also explore first and return to setup later.
- Agent skills now have Installed, Discover, and Registries views, with search, provider filters, expandable details, and installation into the portable Autohand skills library. Autohand and skills.sh are included by default, and you can add public GitHub or HTTPS JSON registries.
- Desktop includes a verified native Autohand Code CLI. If no CLI is installed, Desktop prepares its bundled copy without requiring a separate download. Existing installations are detected, older versions use the CLI's upgrade command, and newer versions are preserved. Background update failures keep the working CLI available.
- About, Changelog, and Third-party licenses use Autohand Sans. About displays the release version and source commit dynamically, with a green check and an action to copy the full commit.

## Reliability

- Registry installation preserves existing skills, copies supporting files, rejects unsafe paths, and identifies installations by source and skill rather than name alone.
- Collapsed navigation panes cannot receive keyboard focus. Shared disclosure motion and reduced-motion support are retained.
- The bundled CLI is checked against its upstream SHA-256 before packaging and again when prepared for use. Its license is included in Third-party licenses.

## Downloads

Installers are published for macOS arm64, macOS x64, Linux x64, and Windows x64. No npm package is published.

This release uses the repository's explicit private and unsigned distribution exceptions. The macOS app has an ad hoc integrity seal, not an Apple Developer signature or notarization. Artifact records identify this signing state and bind downloads to this repository's source commit; they do not claim an official signing identity.
